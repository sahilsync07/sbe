The Golden Rules & Architectural Commandments

Strict commitments and operational guidelines governing image selection, processing, and display

Zero Tolerance

Rule 1: Strict Negative Content Filter

Under NO circumstance may any marketing card include:
• Top Banner Text: "Sri Brundabana Enterprises", "SBE Rayagada", or daily stock dates.
• Bottom Footer Text: "Qty", "Qty:", or isolated carton piece counts.
Rationale: Wholesale buyers must see manufacturer-authentic promotional assets. Internal warehouse stock story cards reveal confidential counts and look unpolished.

4-Stage Pact

Rule 2: Catalog Card Synthesis

When using raw catalog PDF cutouts, follow the exact 4-stage compositor pipeline:
1. Crop out footwear product tightly.
2. Remove solid or messy background cleanly.
3. Upscale & HD enhance contrast and clarity.
4. Composite onto branded wave background with top-right logo, drop shadow, and bottom specs strip (matching Core-1136.png).

Cloud Standard

Rule 3: Semantic Asset Naming

Never upload cryptic WhatsApp filenames (e.g. IMG-20240807-WA0013.jpg).
All Cloudinary assets must be normalized to:
[BRAND]_[MODEL]_[COLOR].jpg
Examples: RELIANCE_XM_9021_NVY.jpg, ACTION_AXEL_BLK_WHT.jpg, CUBIX_50251_GRAP.jpg, EEKEN_2141_BRT.jpg.

Priority Hierarchy

Rule 4: Manufacturer Precedence

Whenever clean manufacturer promotional cards are available in Quick Share / WhatsApp archives (and pass all negative filter checks), they must be strictly preferred over catalog cropped cutouts. Real factory cards contain authentic color grading and typography.

Visual Integrity

Rule 5: Zero AI-Generated Brand Assets

Absolute purge of AI-designed clip art (shoe-prints, cartoon icons, gradient SVG mockups). Use only authentic manufacturer brand logos extracted directly from official physical catalogs or high-res vector scans (Paragon, Eeken, Action, Solea, Paralite, Comfy).

Brand Boundary Isolation

Rule 6: Cross-Brand Matching Prohibition

Models must strictly match within their brand boundary. An Eeken product name ending in MRP1449/- must never match a Paragon EV1449LP slipper. Price tokens (MRP..., RS..., @...) must be stripped before model tokens are evaluated.

The 4-Layer Defense Engine

Multi-tier geometric, photometric, and optical character verification implemented in process_all_quick_share.py

When processing hundreds of WhatsApp media items, optical character recognition alone is insufficient because OCR engines can distort stylized fonts (e.g. reading "Rayagada" as "Rayasada") or miss yellow numbers on black backgrounds. We designed an airtight 4-layer defense pipeline that eliminates 100% of internal status cards:

L-01 01

Geometry & Aspect Ratio Disqualification

Mobile phone story screenshots (WhatsApp status cards) are generated in vertical phone ratios (16:9 or 20:9 vertical, e.g. 720×1600, 540×1200). Official manufacturer marketing assets are square or standard portrait (3:4 or 4:5). Any image with width/height ratio below 0.58 is instantly rejected before running costly OCR.

Aspect Threshold (w / h) < 0.58
Status story catch
L-02 02

Visual Banner Brightness Sampling

SBE WhatsApp status cards characteristically feature solid black header and footer banners overlaying the product photo. The script samples the top 5% strip and bottom 5% strip of the image array. If both strips exhibit an average pixel brightness below 35 (pure black), it is immediately flagged as a status template.

Photometric Test top_lum < 35 &&
bot_lum < 35
Solid banner trigger
L-03 03

OCR Spelling Typo & Date Stamp Denylist

Optical character recognition can transcribe stylized typography with phonetically similar characters. The denylist includes both exact keywords and transcription distortions: rayasada, raygada, brundaban, sbe, s.b.e, along with calendar date regex patterns (e.g. \d{1,2}\s+(Jan|Feb|...)\s+202\d).

Regex Denylist /(rayasada|sbe|
brundaban|\d{2}\s\w{3})/i
Typo & date catch
L-04 04

Footer Qty & Isolated Count Rejection

When yellow text on a black footer drops the label "Qty:", OCR may read only the raw count (e.g. "24", "36", "48"). Layer 4 evaluates the bottom 15% bounding boxes. Any standalone two-digit number matching standard footwear wholesale carton pack sizes causes an automatic block.

Bottom 15% Filter qty|pairs|prs|
^\s*\d{2}\s*$
Carton count block

Catalog Card Synthesis Engine

Automated promotional card compositor implemented in frontend/scripts/generate_catalog_card.py

To convert raw catalog cutouts into cohesive, high-end promotional cards matching the iconic Core-1136.png aesthetic (900×1200 portrait cards), we built an automated 4-stage pipeline:

1. Precision Cropping

Identifies footwear bounding box from PDF catalog sheets, discarding page margins, folio numbers, and adjacent models.

2. Background Removal

Alpha-matting extraction produces a transparent PNG of the footwear cutout with antialiased sole contours.

3. HD Enhancement

Unsharp masking, micro-contrast enhancement, and saturation stabilization to eliminate scan grain.

4. Branded Compositor

Composites onto dynamic wave background, adds soft drop shadow, official brand logo (top right), and bottom specification strip.

cloudStatus.js — Intelligent Dual-Cloud Failover Function 
export function getPreferredImageUrl(product) {
  if (!product) return null;

  // 1. If primary cloud is down, fail over seamlessly to secondaryImageUrl
  if (isPrimaryCloudDown.value && product.secondaryImageUrl) {
    return product.secondaryImageUrl;
  }

  // 2. If primary is down and product has no secondary image, return null cleanly
  if (isPrimaryCloudDown.value && product.imageUrl && product.imageUrl.includes(primaryCloud) && !product.secondaryImageUrl) {
    return null;
  }

  // 3. Normal order: primary imageUrl first, then secondaryImageUrl fallback
  return product.imageUrl || product.secondaryImageUrl || null;
}

Matching Engine & Database Disinfection

Eliminating cross-brand model collisions, price-token pollution, and pseudo-model errors

Bug 1: Eeken 069 → ParaLite EV1449LP

Root Cause: Product name Eeken 069 Black Mrp1449/- had its price 1449 extracted as a model number when no model prefix was found, crossing brand boundaries into ParaLite EV1449LP.
Solution: Strict brand boundary isolation (Eeken only matches Eeken; Paragon only matches Paragon) and complete stripping of price expressions (MRP..., RS..., @...) before model matching.

Bug 2: Action Aptos → Paragon 4809

Root Cause: FOOTWEAR_MRP-399_BLK_MRP399.png carried no real model token and matched purely on price and color to Action Aptos.
Solution: Pseudo-model denylist disqualifies any price-only token (MRP-*, RATE-*, DISCOUNT-*, VIEW-*, SINCE-*). The asset was re-assigned to its true article: Paragon Blot 4809 Mrp399/-.

Discovery: Box Footwear ("Barun" Group)

Root Cause: 139 products under group "Barun" (including BF DRAGON-1, BF DRAGON-3, BF YODHA-1, BF JOGGAR, BF WONDER) had missing images in the UI and were excluded from the Box Packing tab because 'Barun' was absent from boxGroupNames.
Solution: Added 'Barun' to boxGroupNames and linked existing Cloudinary images to the BF Dragon/Yodha articles.

Production Incident & Forensic Audit 2026-09-23 Case Study

Colorway Desynchronization & False Color Matching in Multi-Variant Articles

The Problem: Visual catalog audit across multi-variant Cubix articles identified 5 distinct products where the displayed shoe image directly contradicted the product card's listed colorway:
• CUBIX C 60612: Chikku shoe photo displayed on the Pink card; Pink shoe photo displayed on the Chikku card (inverted swap).
• CUBIX E 21584 SILVER: Displayed a Brown shoe photo with explicit card text CLR BRN.
• CUBIX E 24511: Brown card displayed Grape shoe; Grape card displayed Blue shoe.
• CUBIX E 24514 & 29506: Biscuit card showed Pink shoe; Black card showed Green shoe; Green card showed Brown shoe.
• CBX 15007: Blue card displayed a Grape (CLR GRP) shoe.

Root Causes Identified
  1. Sequential Variant Assignment: In process_cubix and process_florex, matching occurred solely on model numbers (e.g. 24511, 29506). Images extracted from WhatsApp were sequentially linked to the first unfulfilled product without color verification.
  2. Permissive Color Fallback: The legacy matches_color function defaulted to returning True when a color was unparsed, allowing mismatched variants to link.
  3. Card Text vs. Visual Mismatch: Manufacturer marketing cards frequently list all available colorways in text (e.g. CLR PNK, CHIKKU, BLK), but only photograph a single shoe variant. OCR alone was reading all listed colors rather than detecting which variant was actually photographed.
Remediation & Pipeline Hardening
  1. Strict Color Matching: Removed the permissive fallback in process_all_quick_share.py. Only explicit color matches or single-variant badges are accepted.
  2. Zero-Tolerance Mismatch Policy: If a clean manufacturer photo for the specific colorway does not exist, secondaryImageUrl is set to null. Never force an incorrect colorway onto an article.
  3. Automated Database Cleanse: Executed fix_color_mismatches.py across both frontend/ and sbe-hub/, applying 31 precision corrections (swapped 60612 Pink/Chikku, 15007 Blue/Grape, unlinked 21584 Silver, remapped 24511, 24514, 29506, and purged 50525, 60557, 77016, 24506).

Superimposed Pill-in-Pill Architecture

For Paragon Gents and Paragon Ladies, standard button padding creates awkward text-to-logo ratios. We engineered a pill-in-pill chassis lockup:
• The outer chassis is elongated with full rounded radius (rounded-full).
• The left section contains a circular child pill housing the pure white Paragon logo on red. This child pill's top, bottom, and left outer arc superimposes exactly on the outer chassis boundary.
• The right chassis extension contains the category name (GENTS / LADIES) rendered in bold uppercase tracking with high visual contrast.

End-to-End Filled Pill Architecture

Generic UI frameworks place a small rectangular logo inside a padded white button, producing an amateurish, unpolished feel. Our filled-pill architecture:
• Pre-renders each manufacturer logo into a standardized 3:1 aspect ratio pill banner with edge-to-edge background bleed.
• Sets overflow-hidden on the pill button, transforming the button chassis into the logo itself.
• Sourced 100% authentic manufacturer assets from Downloads\Pictures\Logos and vector extractions from the 300 DPI master catalog (including the teal P-Toes brand insignia).

Header Brand Identity Redesign:

• Removed: AI-style yellow shoe-prints icon (fa-shoe-prints) and clashing Times New Roman serif font.
• Implemented: Luxury Swiss editorial typographic lockup:
